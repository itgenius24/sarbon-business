# Документ Высокоуровневой Архитектуры

## Обзор

**Платформа Логистики Sarbon** - это комплексная система обмена грузами и управления логистикой, построенная на Next.js 14, служащая цифровой площадкой, соединяющей владельцев грузов, перевозчиков, водителей и диспетчеров. Платформа обеспечивает эффективную транспортировку грузов через GPS-отслеживание в реальном времени, автоматизированное сопоставление груз-водитель и управление рабочими процессами на основе ролей.

## Архитектурные Паттерны

### 1. Контроль Доступа на Основе Ролей (RBAC)

Приложение реализует комплексный контроль доступа на основе ролей через middleware.js с пятью различными пользовательскими ролями:

- **Перевозчик** (`f81d3c3d-228d-479e-a2b1-9948c98640f2`)
- **Заказчик** (`48871d27-7361-4f69-8fe4-b54daf270739`)
- **Диспетчер** (`785678f2-fae7-4a00-8766-99ea67d3784f` + `first_dispatcher`)
- **Старший Диспетчер** (`785678f2-fae7-4a00-8766-99ea67d3784f` + `top_dispatcher`)
- **Директор** (`527d2017-2dc2-4449-9eeb-08fc1aafa469`)

Каждая роль имеет специфические разрешения доступа к страницам, определенные в middleware.js, с автоматическими перенаправлениями для попыток несанкционированного доступа.

### 2. Модульная Архитектура Бизнес-Логики

Платформа организует бизнес-логику в 35+ специализированных модулей, каждый из которых содержит:
- Основной файл компонента
- Пользовательские hooks для бизнес-логики (`useModuleNameProps.js`)
- Подкомпоненты для специфической функциональности
- Утилиты трансформации данных

### 3. Слоистая API Архитектура

```
Frontend Компоненты → Пользовательские Hooks → API Сервисы → HTTP Клиенты → Backend APIs
```

- **Пользовательские Hooks**: Hooks на основе React Query для получения данных и мутаций
- **API Сервисы**: Доменно-специфичные слои сервисов (auth, functions, items, object)
- **HTTP Клиенты**: Два экземпляра Axios с интерцепторами аутентификации
- **Backend Интеграция**: RESTful APIs с автоматическим обновлением токенов

### 4. Стратегия Управления Состоянием

**Глобальное Состояние (MobX)**:
- `authStore`: Аутентификация пользователя и управление сессией
- `formStore`: Персистентность данных формы при навигации

**Состояние Сервера (React Query)**:
- Кеширование и синхронизация API данных
- Оптимистичные обновления для пользовательских взаимодействий
- Фоновое повторное получение и обработка ошибок

**Локальное Состояние (React)**:
- UI состояние, специфичное для компонента
- Ввод форм и валидация
- Временные трансформации данных

## Архитектура Потока Данных

### 1. Поток Аутентификации

```
Страница Входа → Верификация Телефона → Валидация OTP → Назначение Роли → Перенаправление на Дашборд
```

1. Пользователь вводит номер телефона
2. SMS OTP отправляется через backend API
3. Верификация OTP с определением роли
4. Данные сессии сохраняются в cookies и localStorage
5. Middleware перенаправляет на соответствующий роли дашборд

### 2. Поток Управления Грузами

```
Создание Груза → Назначение Водителя → GPS Отслеживание → Обновления Статуса → Завершение
```

1. **Создание Груза**: Многошаговая форма в модуле CargoTest
2. **Поиск Водителя**: Фильтрация и назначение в реальном времени
3. **GPS Отслеживание**: Обновления местоположения в реальном времени с визуализацией маршрута
4. **Управление Статусом**: Переходы состояний рабочего процесса
5. **Завершение**: Финальное подтверждение доставки и аналитика

### 3. Поток Данных GPS Отслеживания

```
Мобильное Приложение Водителя → Backend APIs → WebSocket/Polling → Frontend Обновления → Визуализация Карты
```

1. Местоположение водителя передается из мобильного приложения
2. Backend обрабатывает и сохраняет GPS координаты
3. Frontend опрашивает обновления через API вызовы
4. Обновления карты в реальном времени с историей маршрута
5. Уведомления о статусе соответствующим заинтересованным сторонам
